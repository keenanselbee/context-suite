PDF Page Interruption Evidence
==============================

The 2026-09-11 checkpoint exercises the actual optional PDFium renderer through
the staged worker. Twenty checks pass for native-phase cancellation, application
deadline expiry and worker process termination. This closes the previously
unmeasured live-renderer interruption slice; it does not complete PDF fidelity,
renderer isolation or visible acceptance.


Method
------

The contract authors a one-page PDF containing 2,000 repeated filled rectangles.
It first completes ordinary rendering, validation and copy publication for that
fixture. Each fault then starts another page render with a checked empty output
reservation. The test observes a live child whose parent PID and executable path
match that worker's pinned renderer, and verifies the output reservation is locked
before injecting the fault. If no live child is observed, the test fails rather
than counting a pre-start interruption as native-phase evidence.

Cancellation uses the normal request token. The client-timeout case expires the
existing test clock after checking the configured 120-second client deadline;
it does not wait for or verify the adapter's separate 60-second wall-clock
deadline. The worker-crash case kills only the owned worker, so native renderer
termination depends on the production job cleanup. Process discovery does not
prove the exact PDFium instruction or painting stage reached before interruption.

After each fault the contract checks the expected cancellation or typed failure,
native and worker exit, reservation/journal/scratch cleanup, and unchanged source
SHA-256 and write timestamp. A fresh worker then publishes both pages of the
existing authored two-page fixture. The test uses no customer files, recycling,
installed state, Explorer registration or live licensing service.
