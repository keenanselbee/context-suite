SVG Engine Build and Protocol
=============================

`proprietary/src/ContextSuite.Svg.Native` contains the private Rust source for a
bounded static SVG-to-RGBA renderer. This tool builds an isolated executable from
that source and the checked-in lockfile. It neither installs an engine nor uses a
stocked binary. Rust 1.98.1, Python 3.11 or newer, and a prepopulated Cargo home
containing the official locked crates are required. The recipe requires the
`x86_64-pc-windows-msvc` host toolchain and builds for that host offline with
locked dependencies, release optimization, and the static C runtime. The host
assertion preserves the executable identity generated by the existing implicit
host build. Its output is under `.codex-temp/svg-engine-build`.

```powershell
& .\tools\svg-engine\Build-SvgEngine.ps1 -CargoHome '<prepared official Cargo home>'
python .\tools\svg-engine\Test-SvgEngine.py '<Executable from build result>'
```

The build checks the lockfile hash, explicit dependency pins, the 63-package
inventory and local license-file digests. Before compiling, it compares each
cached `.crate` archive's SHA-256 with `Cargo.lock`, then compares every unpacked
source file byte for byte with its archive and refuses unreviewed files. It also
checks source snapshot stability, the Rust version and installed target. It
writes `source-verification.json` and `build-provenance.json` beside the executable;
the latter records source, inventory, verifier, target, toolchain and runtime
hashes. It prints the executable path and SHA-256 for the private runtime pin.
The parent release process must review and pin that exact identity before adding
it to a candidate. [Dependency evidence](../../assets/third-party/svg/README.md)
belongs to the public source tree; the Rust implementation remains private.


Runtime Contract
----------------

The executable accepts exactly `inspect` or `render <width> <height>`. It reads up
to 1 MiB plus one byte from inherited standard input. It never receives a source
or destination path. On success, `inspect` writes one UTF-8 JSON object; `render`
writes a little-endian `uint32` JSON-byte length, the same JSON shape, then
`width * height * 4` tightly packed **straight RGBA8** bytes. Zero-alpha pixels
have zero RGB. The binary header fields are `Abi` (1), `IntrinsicWidth`,
`IntrinsicHeight`, `Width`, `Height`, `MaximumSide`, `MaximumPixels`,
`FontFingerprint`, and `FontNotices`. Native viewport dimensions in `inspect` are
ceil-rounded and may exceed rendering limits; the exact positive intrinsic
floating-point dimensions are bounded at 1,000,000 per side.

The normal render limit is 4,096 pixels per side and 16,000,000 total pixels.
Documents with filters have limits of 1,024 pixels per side and 1,000,000 total
pixels. The requested integer dimensions must match the intrinsic aspect ratio
within one pixel of ordinary integer rounding. Raster scaling is uniform, with
transparent residual pixels when rounding leaves canvas space. The managed
adapter owns the 90-second deadline, process memory job, cancellation, source
lease, PNG encoding and validation. Application orchestration owns publication.

Exit 2 means invalid input or arguments, 3 unsupported content, 4 a resource
limit, and 6 an engine or transport fault. Standard error contains one short
reason token and never SVG content. Success has empty standard error.


Admission Boundary
------------------

The native preflight limits XML to 2,000 elements and depth 64 and refuses DTDs,
processing instructions, scripts, active/animation elements, unknown elements or
attributes, foreign namespaces, CSS animation/imports, external references,
missing local references, and cyclic or excessive `use` expansion. It admits
static presentation attributes and bounded static CSS rules, paths, gradients,
patterns, clipping, masks, text, and a restricted filter set. Images must be data
URL 8-bit PNG or JPEG: at most 8 images, 384 KiB decoded per image, 1 megapixel
each, and 2 megapixels combined. Embedded animation, PNG ICC/gamma/chromaticity/
EXIF, and JPEG EXIF/ICC/other color-affecting metadata are refused. Malformed
geometry, local paint cycles, renderer warnings, and missing or unsupported text
glyphs cause refusal rather than silent omission.

An embedded image directly beneath the SVG or ordinary groups must appear in
the renderer tree; otherwise the document is refused. Images in `defs`, `use`,
mask, clip, and pattern content are decoded during preflight but are not counted
one for one in the top-level renderer tree. Repeated local `use` may create more
rendered instances than source images. Renderer warnings still cause refusal.
This leaves exact visibility of images nested in paint resources outside the
top-level count check; the bounded static subset and independent pixel tests
cover the admitted cases.

The [W3C clipPath content model](https://www.w3.org/TR/css-masking-1/#the-clipPath-element)
permits shapes, text, and `use` as rendered children. An image can have a
`clip-path` applied to it, but an image *inside* `clipPath` is outside that model
and is refused by the renderer warning gate. The pixel checks cover repeated
image `use`, images in a mask and pattern, and an image clipped by a valid path.

Only a fixed bounded set of Arial, Segoe UI, Times New Roman, and Courier New
Windows font files is loaded from the OS Windows directory. The font fingerprint
hashes the actual loaded bytes. Only substitutions and glyph fallbacks are
reported. Each notice is bounded to 256 characters; more than 32 distinct
notices causes resource refusal. No font is shipped.
This is a deliberately bounded static SVG subset, not a general SVG browser.
